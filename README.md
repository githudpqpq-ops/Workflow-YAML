# GitHub Actions — настройка Workflow средствами YAML

Учебный проект по теме 3.1.48. Реализованы все три практических задания из методического материала.

## Состав репозитория

- .github/workflows/basic-workflow.yml — задание 1 (30 баллов): ручной запуск, Ubuntu, два последовательных шага, одиночная и многострочная shell-команды.
- .github/workflows/ci-filter.yml — задание 2 (35 баллов): push только в main и только при изменениях src/** или package.json; checkout, Node.js 20, проверка node -v и npm -v.
- .github/workflows/advanced-pipeline.yml — задание 3 (35 баллов): параметры choice (staging/production), string (номер сборки), boolean (режим отладки); независимые Linux- и Windows-задачи; полная история Git и подсчет коммитов.
- src/index.js — исходный файл для проверки фильтрации путей.
- package.json — конфигурация Node.js-проекта.

## Проверка заданий

### Задание 1
Откройте Actions, выберите Basic Workflow, нажмите Run workflow. Убедитесь, что оба шага завершились успешно.

### Задание 2
Измените src/index.js или package.json и отправьте commit в main. Проверьте запуск CI Filter. Для проверки отрицательного сценария измените файл вне отслеживаемых путей: этот workflow не должен запускаться.

### Задание 3
Откройте Actions, выберите Advanced Pipeline и нажмите Run workflow. Выберите staging или production, укажите номер сборки и debug-флаг. Убедитесь, что Linux Build и Windows Build завершились успешно. В логах Linux проверьте результат git rev-list --count HEAD.

## Критерии оценки из задания

| Критерий | Баллы |
|---|---:|
| Корректность синтаксиса и файловой структуры | 20 |
| Настройка триггеров запуска | 20 |
| Организация задач и сред | 20 |
| Реализация шагов run и uses | 25 |
| Оформление, комментарии и работоспособность | 15 |
| **Итого** | **100** |

Все YAML-файлы находятся в обязательном каталоге .github/workflows/. Для проверки фактической работоспособности необходимо запустить workflow во вкладке Actions и изучить логи.
